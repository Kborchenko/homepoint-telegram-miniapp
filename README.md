# HOMEPOINT · Telegram Mini App

Единое приложение для первичного отбора и семидневного обучения координаторов HOMEPOINT.

## Что уже работает

- Telegram-профиль кандидата: имя, username, фото и ID;
- таймер первичного тестирования запускается только по кнопке «Запустить 24 часа»;
- пять демонстрационных ситуационных вопросов и итоговый результат;
- запрос персонального доступа после завершения теста;
- отдельный кабинет менеджера по адресу `/manager/`;
- семь последовательных учебных дней;
- открытие следующего дня в ближайший будний день в 00:00 МСК;
- встроенная библиотека референсов;
- статическая сборка для GitHub Pages;
- схема Supabase с RLS для серверного таймера, доступов и прогресса.

В локальном демо состояние хранится в браузере. Это позволяет проверить весь интерфейс без ключей. В боевой версии интерфейс подключается к Supabase, а Telegram `initData` обязательно проверяется серверной функцией до выдачи пользовательской сессии.

## Запуск

```bash
pnpm install
pnpm dev
```

Откройте `http://localhost:3000`. Кабинет менеджера доступен на `http://localhost:3000/manager/`.

## Проверка

```bash
pnpm lint
pnpm typecheck
pnpm build
```

Статическая сборка появится в `out/`.

## Подключение Supabase

1. Создайте бесплатный проект Supabase.
2. Выполните [`supabase/schema.sql`](./supabase/schema.sql) в SQL Editor.
3. Скопируйте `.env.example` в `.env.local` и заполните публичные значения Supabase.
4. Добавьте серверную функцию, которая проверяет подпись Telegram `initData` с помощью токена бота и создаёт короткую пользовательскую сессию.
5. Никогда не помещайте `TELEGRAM_BOT_TOKEN` в переменную с префиксом `NEXT_PUBLIC_`.

## GitHub Pages

Workflow `.github/workflows/deploy-pages.yml` собирает `out/` и публикует его в Pages. В настройках репозитория выберите источник **GitHub Actions** и добавьте два секрета:

- `NEXT_PUBLIC_SUPABASE_URL`
- `NEXT_PUBLIC_SUPABASE_ANON_KEY`

GitHub Pages размещает интерфейс бесплатно. Supabase отвечает за защищённое состояние, доступ менеджера и серверное время.

## Важное про 24 часа

Клиентский таймер в интерфейсе — только визуальное отображение. Источником истины в production должна быть строка `assessment_sessions`: `started_at` и `expires_at` создаются атомарной функцией `start_assessment()` на сервере. Поэтому очистка браузера, другой телефон или изменение часов не дают кандидату новые 24 часа.
